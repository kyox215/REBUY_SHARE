## 1. 先读什么

按 00 → 11 的顺序阅读。00 说明产品范围，01/02 约束买家客户端视觉和页面行为，03/04 说明平台角色与技术边界，05 规定实施阶段和验证门，06 是当前获准的本地视觉原型执行合同，07/08 是账号规划与结构图，09 是 A0 ADR/威胁模型，10 是 A1 Auth spike 执行合同，11 记录独立测试连接骨架与发布边界。

本目录不是生产系统，也不是已经部署的网站。任何本地预览、静态截图、虚构数据或浏览器检查都只能证明相应的本地视觉/交互状态，不能等同于数据库、RLS、隐私、支付、部署、生产数据或业务验收。

## 3. 当前权威关系

1. 本 README 负责导航和文档状态；具体产品范围以 00 为准。
2. 买家客户端视觉和页面行为以已经批准的 01/02 为准；03/04/05/06 不会把客户端规范扩展为商家后台视觉规范；07/08/09/10 只定义账号安全与验证门禁，不改变 P1 原型的无后端边界。
3. 本轮新决定明确这是多商家批发与零售平台。过去较窄的供应商到零售商方案、旧原型或历史讨论只能作参考；若与 00 或已批准的 01/02 冲突，以当前权威决定为准。
4. 任何改变角色、权限、数据归属、价格规则、支付责任、隐私风险、外部连接、生产写入、验收标准或回退方式的新增需求，都必须形成新的 Owner 决定，不能在执行中悄悄扩大范围。

## 4. 当前下一步

当前批准覆盖 P1 本地视觉原型，以及账号文档进入 A0 的整理执行；A1 仍必须等待 A0 验收。执行顺序是：

1. 使用 01/02/06 制作移动优先、桌面响应式、无后端、纯虚构数据的本地视觉原型。
2. 达到 06 定义的首个有效预览门槛后，启动本地开发服务器，并由主线程在 Codex 侧边栏打开；服务器在本轮完成前保持运行，通过 HMR 观察后续改动。
3. 完成 P1 的页面、交互、响应式和控制台检查后，由 Owner 决定是否进入 P2；账号路径必须先通过 A0，再按 10 执行独立 Auth spike；本目录文档任务本身不执行网站代码、依赖、数据库或部署。

## 5. 证据边界

- “文档已完成”只表示规划文档已经整理并通过文档级检查。
- “本地视觉原型已完成”只表示本地页面和交互达到 06 的门槛，并不表示认证、权限、库存、订单、售后、RLS、隐私或生产系统已经完成。
- “本地浏览器检查通过”只表示指定浏览器和视口下的可见行为通过，不能替代真实环境、迁移、备份恢复、权限隔离、监控、法律/税务和 Owner 生产批准。
- 本目录中的示例商品、商家、订单、客户和地址均应为虚构合成数据；不得把真实客户或商家资料复制进文档或原型。

本轮文档整理不创建产品代码、网站脚手架、依赖、数据库、Storage bucket、部署、支付账户、外部 API 连接、真实业务写入或真实数据迁移。不连接 Supabase、OAuth、SMTP 或 production。本轮已完成独立只读安全复核，结论无阻塞；仍有 A1/A4/A5 未验证风险，不构成安全验收或生产批准。不做哈希检查；09/10 的 A0/A1 证据、风险和后续高风险门槛见 [V1 实施路线与验证计划](./05-V1实施路线与验证计划.md)。
