## 1. 范围与非授权边界

### 1.1 本文做什么

- 将买家端已批准的首页、分类、商品详情、购物车、结算、订单、我的映射到统一 UI 系统。
- 为未来商家后台建立工作台、商品、库存、订单、售后、成员与权限的页面和组件映射。
- 明确当前 Prototype 组件是复用、扩展还是新增，避免重复编写同一导航、价格、状态、商家分组或二手事实逻辑。
- 固化 390/430/768/1024/1440 视口下的结构验收要求。

### 1.2 本文不授权

- 商家后台目前只是设计映射，不是当前代码、路由、数据库、Supabase、RLS、API、权限或生产写入授权。
- 不因画出商品、库存、订单、售后、成员或权限页面，就代表这些模块已经实现或可连接真实数据。
- 不改变 00/01/02 的买家业务边界：五项导航、自动批发定价、多商家购物车/订单、二手关键事实、zh/it/en、44px 触控、键盘与无障碍仍然有效。
- 不加入微信商品/订单同步或 API；参考设计中的 AI、时间跟踪、审批、团队和计费内容只作视觉证据。
- 不连接真实认证、生产数据、支付、物流、税务、ERP 或外部服务。

## 2. 当前 Prototype 组件盘点

当前代码中已经存在以下买家端组件，应优先复用或扩展：

| 组件 | 当前职责 | 映射结论 |
|---|---|---|
| `AppShell` | 顶部品牌/返回/搜索/购物车、内容区、五项底部导航、语言上下文 | 只复用/扩展买家端；未来商家后台不塞入 `AppShell` 条件分支 |
| `MerchantShell` | 当前不存在 | 未来新增、P6 Gate；独立承载后台侧栏、组织/店铺上下文和后台工具栏，不改变买家 `AppShell` |
| `BrandMark` / `NavigationItem` / `TopToolbar` / `Surface` | 当前未独立抽出为共享 primitive | 未来规划为共享基础 primitive/token；复用视觉代码，不复制品牌、导航项、顶部工具和内容面样式 |
| `ProductCard` | 商品图、类型、名称、商家、价格、库存和加购 | 复用基础结构；扩展 `compact` 与 `used-expanded` 两种卡片变体 |
| `UsedFacts` | 成色、缺陷、电池、保修的事实列表；当前 compact 只显示部分字段 | 扩展二手卡的 compact 规则，Owner 9C 下直接显示四项关键事实 |
| `PriceBlock` | 按角色计算零售价/批发价、MOQ、阶梯价 | 复用；价格继续由身份/规则决定，不新增手动批发模式 |
| `SellerGroup` | 购物车按商家分组、商品行、数量、商家小计 | 复用并扩展配送/限制/价格变化行，继续作为订单商家组基础 |
| `StatusBanner` | info/success/warning/danger 状态提示和语义 role | 复用；扩展离线、403、库存过期、价格变化、重复提交文案与恢复动作 |
| `FilterSheet` | 分类/库存/商品类型筛选、排序、清除和应用 | 复用交互结构；扩展品牌/价格/商家等经 Owner 批准的条件 |
| `QuantityStepper` | 普通商品数量的最小值/最大值控制 | 普通商品复用；二手商品使用固定数量呈现，不复制一个可调步进器 |
| `SpriteImage` | 使用本地 `product-sprite.png` 的合成商品资产 | P1 复用；未来真实资产需独立许可和媒体合同，不把参考素材资产复制进来 |

当前实现还没有授权创建商家后台组件。后续新增组件必须先确认它不能由以上组件通过变体、组合或数据适配完成。

### 3.1 买家信息层级合同

- 首页只保留搜索、分类和高密度商品流，不放 KPI、收入、工作时长、环形统计或后台报告。
- 分类/搜索首屏必须能比较商品名称、商家、适用价格和库存；二手结果至少显示成色/缺陷或电池摘要。
- 商品详情首屏先确认购买事实，再展示规格政策；二手成色、缺陷、电池、保修不默认折叠。
- 购物车和订单以商家为第一分组；平台批次只负责汇总，不掩盖商家子订单。
- 价格由游客/零售/已认证批发身份自动决定；任何身份样本入口只能是受控演示，不得成为生产模式开关。
- 任何库存、价格、批发资格变化都指向具体商品和商家，不能静默改价、删行或重建订单。

### 6.1 统一选择器映射

- 买家端分类排序和顶部语言选择器都复用 `SelectMenu<T extends string>`；排序仍使用 `featured`、`priceLow`、`priceHigh`，语言仍使用 `zh`、`it`、`en`，回调和 `document.documentElement.lang` 同步逻辑不变。
- `SelectMenu` 是本地 Client Component，负责触发器、弹层、选项焦点和键盘交互；`FilterSheet` 仍负责筛选 Sheet 的打开/关闭、清除、应用和筛选状态，不把两套交互合并成业务巨型组件。
- 不得用浏览器原生 `<select>` 的展开层承载产品视觉；商品真实筛选、分类入口和五项买家导航不通过选择器替代，也不因本批新增 primitive 改变。
- 未来 MerchantShell 可以共享该 primitive/token，但商家后台仍未授权实现；选择器不能携带买家/商家业务条件分支。

- 返回与下钻：商品详情继续使用既有 `detailOrigin`，返回时保留来源品类结果；目录返回操作清除旧搜索/筛选/排序，避免不同品类间残留陈旧条件。五项导航仍保持 active 分类状态，二手事实、批发自动定价、多商家购物车/订单不变。

## 7. 状态映射合同

| 状态 | 买家端表达 | 后台映射 | 恢复动作 |
|---|---|---|---|
| `loading` | 保留商品/商家组结构的骨架，标题和范围可读 | 表格/摘要骨架，避免整页空白 | 等待、刷新或重试；不清空筛选 |
| `empty` | 说明无商品、无订单或空购物车，并提供分类/清除筛选/去购物 | 说明无待办、无商品或无售后并提供创建/筛选 | 去发现、清除条件、创建首条资料 |
| `error` | 说明影响范围和可重试入口 | 指向失败表格/保存区，不隐藏已填内容 | 重试、返回、保留表单 |
| `offline` | 区分可查看缓存与不可提交 | 禁用写入并显示重连状态 | 恢复网络后重试；不重复提交 |
| `403`/无权 | 说明登录、批发认证或资源权限问题，不泄露内部字段 | 显示组织/店铺范围不足和申请权限入口 | 登录、切换已授权店铺或联系管理员 |
| `low stock` | 显示库存紧张、可购上限和商品行 | 库存异常、阈值和变动原因 | 调整数量、补货或下架 |
| `out of stock` | 主行动禁用，显示无货文字；二手显示已不可购买 | listing/单件锁定或售出状态 | 下架、替代商品或恢复库存 |
| `price changed` | 指出商家/商品旧价与新价，要求确认 | 记录价格版本和变更原因 | 返回购物车确认，不静默改价 |
| `stale stock` | 阻止提交并定位商品 | 记录预留/并发冲突 | 删除、调整或重新检查库存 |
| `duplicate submit` | 查询原提交结果，不创建第二个订单 | 使用幂等键和事件查询 | 显示原批次、处理中或明确失败 |
| `partial failure` | 分开显示成功商家子订单和失败商家组 | 保留成功事件，失败组可重试 | 只处理失败组，不重建成功订单 |
