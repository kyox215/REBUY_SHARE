# 平台角色与业务模块

文档状态：V1 业务和权限规划执行稿  
适用范围：平台管理端、商家管理端和买家客户端的职责边界  
安全原则：浏览器输入不可信；权限必须在受信任服务端校验，RLS 是数据库层最终隔离，不以隐藏前端字段作为安全控制。

## 1. 角色模型

平台将身份、组织成员关系和店铺范围分开建模：

- users 表示认证主体和平台用户身份。
- organizations 表示商家组织或批发客户组织；商家组织可以拥有多个店铺。
- memberships 表示用户在组织中的成员关系和角色，并可进一步限制到某个店铺。
- 游客是未认证的客户端访问状态，不是一个拥有后台权限的持久角色。
- 零售客户和已认证批发客户都是买家身份；批发资格是经过审核的业务状态，不是用户可以手动切换的显示模式。
- 一个用户可以同时属于不同组织，服务端每次请求必须明确当前组织和店铺上下文，不能使用上一次页面选择作为授权依据。

角色权限遵循最小权限、职责分离和可追溯原则。平台级高风险动作，例如批准入驻、改变权限、批量修改价格、删除或导出敏感资料，后续应按风险配置复核或二次确认。

## 2. 权限矩阵

下表是能力方向矩阵，具体 API 还必须进行对象级、字段级和状态级授权。“可”不代表可以绕过状态、审计或服务端校验。

| 角色 | 权限范围 | 平台配置/组织 | 入驻与批发审核 | 商品/价格/库存 | 订单与售后 | 客户资料 | 审计与导出 |
|---|---|---|---|---|---|---|---|
| 平台管理员 | 全平台，按职责分配 | 管理平台规则、分类、组织和成员；高风险动作留痕 | 可审核或授权审核；可暂停组织/店铺 | 可处理平台级状态和异常，不代替商家经营 | 可查看跨商家汇总和异常；不得篡改原始事件 | 仅按业务需要访问最小字段 | 可查看安全审计；敏感导出需单独授权和记录 |
| 审核/客服 | 被分配的平台工作范围 | 不可改变平台角色或组织所有权 | 可处理入驻、批发认证、补件和客服工单 | 原则上只读商品/库存状态，不可改商家成本和价格 | 可查看并处理支持范围内的订单/售后，不可越权退款 | 仅查看处理所需的联系方式和订单资料 | 可写处理记录；不可读取密钥、完整证件或无关客户数据 |
| 商家 Owner | 自己的组织及所属店铺 | 管理本组织成员、店铺设置和商家资料 | 可提交/补充申请；不可批准自己组织 | 管理自己店铺的商品、定价、上架和库存 | 管理自己订单、配送准备和售后响应 | 只能查看自己订单所需的客户最小资料 | 查看自己组织的操作记录；不可清除平台审计 |
| 商家员工 | 被分配的组织/店铺及功能 | 不可管理组织 Owner、权限边界或平台设置 | 可协助准备资料，不可批准 | 按授权执行商品、库存或订单工作 | 按授权处理订单/售后；不能跨店铺操作 | 仅查看当前工作所需字段 | 写入本人操作记录；不可导出全量客户资料 |
| 游客 | 公开客户端资源 | 不可 | 只能查看公开的申请/登录入口 | 浏览公开分类、商品、零售价和公开库存状态 | 可使用临时购物车；不可提交订单或查看订单 | 不产生持久客户资料 | 不可 |
| 零售客户 | 本人账户、购物车、订单和地址 | 管理自己的基本资料和显示设置 | 可申请批发认证；查看自己的申请状态 | 查看零售价；购买普通或二手商品；不可看批发条件 | 提交并查看自己的批次/子订单，按规则发起售后 | 只能查看和修改自己允许的资料 | 只能查看与本人相关的状态历史 |
| 已认证批发客户 | 本人账户及所属批发组织 | 查看自己的认证和组织状态；不可自行提升权限 | 查看认证状态和补件要求 | 自动查看批发价、起订量和必要阶梯价；仍受库存和商家规则约束 | 提交并查看自己的批次/子订单，按规则发起售后 | 只能查看本人和订单所需的最小资料 | 只能查看与本人订单/认证相关的状态历史 |

## 4. 业务状态与允许动作

状态是业务事实，不是单纯的颜色或标签。任何状态迁移都需要服务端检查当前角色、对象归属、前置状态、幂等请求和审计记录。

### 4.1 商家入驻状态

| 状态 | 含义 | 允许的主要动作 |
|---|---|---|
| “draft” | 申请尚未提交 | 申请人补充资料、保存草稿 |
| “submitted” | 已提交等待接收 | 平台接收并进入审核队列 |
| “under_review” | 审核处理中 | 审核/客服查看必要资料、记录意见 |
| “needs_info” | 需要补件或澄清 | 申请人补充；审核重新检查 |
| “approved” | 平台批准入驻 | 建立/启用店铺，按权限运营 |
| “rejected” | 本次申请未通过 | 按政策查看结果，重新申请需明确新申请 |
| “suspended” | 已暂停经营或访问 | 平台记录原因；商家按指引申诉/整改 |
| “withdrawn” | 申请人撤回申请 | 只读保留记录，后续重新提交需新流程 |

批准不能自动向申请人赋予平台管理员权限，也不能跳过店铺、成员和商品状态。

### 4.2 商品状态

| 状态 | 含义 | 客户端行为 |
|---|---|---|
| “draft” | 商家内部编辑中 | 不公开 |
| “pending_review” | 需要平台或商家规则检查 | 不公开或只对审核角色可见 |
| “active” | 已发布且可被规则匹配 | 按库存、价格和身份展示 |
| “inactive” | 暂时下架 | 不可新购；已有订单仍按订单状态处理 |
| “rejected” | 未通过内容/合规检查 | 不公开，保留修订原因 |
| “archived” | 不再经营 | 只读保留历史引用 |

### 4.3 库存状态

| 状态 | 普通商品 | 二手设备 |
|---|---|---|
| “in_stock” | 可售数量大于零 | 唯一单件可售 |
| “low_stock” | 低于商家配置阈值 | 可选的“即将售出”提示，但仍只能购买一件 |
| “reserved” | 已被有效订单/流程预留 | 该单件不可被其他提交占用 |
| “out_of_stock” | 可售数量为零 | 单件已售出、锁定或失效 |
| “disabled” | 人工停用或数据异常 | 人工停用、事实不完整或审核阻断 |

普通库存允许合法数量调整；二手单件不允许通过数量编辑器复制或增加单位。

### 4.4 订单状态

订单需要区分 checkout_batch 与商家子订单：

| 状态 | 适用对象 | 含义 |
|---|---|---|
| “draft” | 结算上下文 | 用户尚未提交 |
| “pending_submit” | 批次 | 正在做价格、库存、资格和地址校验 |
| “submitted” | 批次 | 已接受提交，等待子订单确认 |
| “partially_confirmed” | 批次 | 一部分商家子订单成功，另一部分需处理 |
| “confirmed” | 子订单/批次 | 商家子订单已建立并可进入处理 |
| “processing” | 子订单 | 商家处理中 |
| “ready_to_ship” | 子订单 | 已准备配送/交付 |
| “shipped” | 子订单 | 已进入配送流程，有数据时显示跟踪 |
| “completed” | 子订单/批次 | 按业务规则完成 |
| “cancel_requested” | 子订单 | 已提出取消，等待规则处理 |
| “cancelled” | 子订单 | 已取消，保留原因和事件 |
| “failed” | 批次/子订单 | 未能建立或继续，必须说明影响和下一步 |

订单状态不可因为页面刷新而凭客户端状态推断；客户端只能呈现服务端返回的状态和事件。

### 4.5 售后状态

| 状态 | 含义 |
|---|---|
| “requested” | 客户已提交售后申请 |
| “under_review” | 商家或平台正在查看事实和证据 |
| “awaiting_customer” | 需要客户补充资料、图片或确认 |
| “awaiting_merchant” | 需要商家提供处理方案或证据 |
| “approved” | 申请按当前政策允许继续 |
| “rejected” | 申请不符合当前政策，并保留理由 |
| “in_progress” | 已进入商家/平台处理 |
| “resolved” | 已形成处理结果 |
| “closed” | 双方完成确认或超时关闭 |

V1 不把自动退款或支付结算写入状态机。若未来增加补偿、退款或平台分账，必须另开支付、税务和隐私专项审查。

## 5. 客户管理边界

### 5.1 最小必要 PII

在完成身份、订单、配送或售后任务所必需时，系统最多使用：

- 认证账户标识和必要的显示名称。
- 为登录/通知所需的联系方式；展示时按场景遮蔽。
- 订单所需的收货地址字段；仅对订单相关商家和授权客服可见。
- 批发认证所需的主体和证明资料；放在私有资料存储，按审核权限短时访问。
- 售后处理所需的沟通和证据引用，不复制无关个人资料。

客户端原型只使用“示例客户”“示例组织”“虚构地址”等合成文本，不出现可关联真实个人的姓名、邮箱、电话、地址或证件信息。

### 5.2 不可见字段

以下信息不能通过前端隐藏来“保护”，必须在 DTO、服务端授权、RLS 和日志策略中阻断：

- 用户认证密钥、会话令牌、服务角色密钥和内部凭据。
- 商家采购成本、毛利、供应商、仓位、批次、内部 SKU 映射和审核备注。
- 平台内部风控分数、客服内部备注、未公开审核理由和跨商家调查信息。
- 其他商家、其他客户、未授权订单和未授权地址。
- 完整证件原件、与当前任务无关的联系方式以及未授权的售后证据。
- 数据库表名、内部错误堆栈、调试对象和审计写入凭据。

### 5.3 客户资料访问原则

1. 客户只能读取和修改自己的允许字段。
2. 商家只能按自己的订单、店铺和售后范围读取最小字段。
3. 平台审核/客服只能读取当前工单或审核所需字段；高风险资料需要额外授权和审计。
4. 所有服务端读取使用明确的组织、店铺、用户和状态条件；不能用“前端传来的 store id”作为唯一授权依据。

## 6. 不包含任何微信同步

平台不接收或发送微信商品、订单、库存、客户或营销数据；不调用微信接口，不设计微信专用认证、后台或同步任务。未来普通网页分享链接属于浏览器可访问链接能力，不改变平台的多商家、权限和数据边界。

## 7. 业务模块之间的责任边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| 身份与权限 | 用户、成员、角色、批发资格和服务端授权 | 用前端开关代替认证或授权 |
| 组织与店铺 | 商家申请、组织、店铺和成员范围 | 代替平台审核或暴露跨商家资料 |
| 商品与分类 | 商品、变体、listing、分类和公开购买事实 | 商家内部采购/财务字段 |
| 价格 | 零售价、批发价、起订量、阶梯价匹配 | 未批准的复杂促销和支付折扣结算 |
| 库存 | 数量库存、单件库存、预留和变动记录 | ERP、仓储自动化和未经批准的迁移 |
| 订单 | 批次、子订单、商品项、状态和事件 | 在线支付、平台分账和自动退款 |
| 售后 | 申请、证据、责任人、状态和沟通记录 | 未定义的法律/税务结论 |
| 审计 | 关键动作、操作者、对象、前后状态和请求标识 | 把完整 PII 或令牌写入日志 |

当前所有模块均只进入规划；本任务不创建数据库、服务端 API、浏览器代码或外部连接。
