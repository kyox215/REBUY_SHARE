合同范围：本地、无后端、虚构数据的买家客户端视觉和交互原型  
证据等级：本地视觉/交互证据，不是生产验收。

## 1. 准确范围

原型采用移动优先、桌面响应式布局，必须覆盖：

- 首页。
- 分类目录和搜索结果。
- 商品详情。
- 购物车和结算。
- 订单批次、商家子订单和订单详情。
- 我的，包括身份样本、批发认证状态、语言、深色模式和无障碍设置入口。

客户端底部导航固定为：首页、分类、订单、购物车、我的；搜索放在顶部。视觉规则沿用 [客户端苹果风格设计规范](./01-客户端苹果风格设计规范.md)，页面结构和边界状态沿用 [客户端 V1 页面线框图](./02-客户端V1页面线框图.md)。

## 2. 必须可点击演示的交互

| 交互 | 最小演示要求 |
|---|---|
| 主导航 | 五项底部导航可点击，切换后页面和当前状态清楚 |
| 搜索/筛选 | 可输入虚构关键词；可演示分类、库存、价格或商品类型筛选；可清除条件 |
| 商品详情 | 至少一个普通商品和一个二手设备可从列表进入详情 |
| 角色视图 | 游客只能查看公开目录并不能提交；零售样本看到零售价；已认证批发样本自动看到批发价、起订量和必要阶梯价 |
| 普通/二手差异 | 普通商品可以调整数量；二手设备固定单件，并显示成色、缺陷、电池健康和保修 |
| 多商家购物车 | 购物车按商家分组，显示各组小计和商品边界 |
| 订单结果 | 一次本地提交演示一个订单批次，并可进入多个商家子订单 |
| 主题与语言 | 深色模式可切换；中文/意大利语/英语可切换且不产生关键文字溢出 |

原型为演示角色差异可以提供受控的“身份样本”入口或开发态入口，但不能把它设计成生产用户手动切换零售/批发价格的模式开关。正式产品由认证身份和服务端规则自动决定价格。

## 3. 数据和视觉资产

- 所有商品、商家、订单、客户、数量、状态和地址都是完全虚构的合成数据。
- 不出现真实姓名、邮箱、电话、地址、证件、客户记录、商家记录或生产订单。
- 商品必须有可识别、真实感的视觉资产，例如自制或已获准使用的本地图片/插画；不能只用空灰色占位块。
- 资产不通过运行时外部请求获取，不在原型中接入外部商品源；后续实现需记录资产来源和许可。
- 普通商品展示数量库存、价格和可售状态；二手设备展示唯一单件、成色、缺陷、电池健康、保修和购买事实。

## 4. 明确不实现

本地原型不实现真实登录、真实认证、后端、数据库、Supabase、RLS、Storage、支付、库存写入、订单持久化、自动退款、物流、税务、ERP、微信接口或任何外部服务连接；不发布、不调用 Sites 托管，也不接触生产数据。点击提交只改变本地演示状态，不产生真实订单或业务写入。

原型不能显示内部成本、毛利、仓位、供应商批次、内部审核备注、证件原文、服务密钥或其他不可见字段。

## 5. 有效预览与 Owner 验收门槛

以下条件构成有效本地预览的最低门槛；当前原型已有对应的本地技术/主代理浏览器检查证据，标题层级、统一选择器与分类目录 IA 修订已完成，Owner 已确认分类目录 IA 通过并重新冻结 G0；全流程实测结果见[本批 manifest](./evidence/G0-P1/2026-08-25-full-experience-acceptance/README.md)：本轮无落盘 PNG，不能替代后续专项或生产验收：

- 首页已经呈现真实产品方向：可识别商品资产、商品名称、适用价格、商家和库存事实可见。
- 底部五项导航全部可见且可点击。
- 至少一个商品能从首页、分类或搜索进入商品详情。
- 本地编译成功；启动后的本地 URL 返回非错误响应。
- 首屏没有明显文字重叠、横向溢出或固定导航遮挡主要内容。

达到门槛后，主线程可以在本地预览中进行后续检查；本地服务器、HMR 或 Codex 侧边栏只证明本地状态，不构成 Owner 或生产验收。若后来改动影响视觉或交互，应重新做受影响范围检查。

## 6. 最终验证

实现完成后，按项目现有脚本运行项目相关的 lint、typecheck、build；再进行移动和桌面页面检查，至少覆盖 390px、430px 移动视口，以及窄桌面和宽桌面视口。

关键交互必须逐项检查：五项导航、搜索/筛选、商品详情、零售/批发样本、普通/二手差异、多商家购物车、订单批次/子订单、深色模式和三语切换。检查无重叠、无横向溢出、无关键文字裁切、无控制台阻塞错误，并保留失败状态的可恢复提示。

这些检查只证明本地原型的视觉和交互状态，不能替代 G1 工程底座与环境隔离、G2-A0 账号安全审查、G2-A1 独立 Auth spike、生产登录、授权、RLS、迁移、真实库存、支付、隐私、部署、监控或业务验收。
