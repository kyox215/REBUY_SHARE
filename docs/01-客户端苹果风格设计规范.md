# 客户端苹果风格设计规范

文档状态：Owner 已批准（2026-08-25，V1 买家客户端）  
适用范围：多商家批发与零售购物平台的手机优先客户端  
语言：中文、意大利语、英语  
示例数据：本文所有商品、商家、数量和订单均为虚构，不含真实客户、商家、地址、邮箱或其他 PII。

## 1. 目标与非目标

### 1.1 目标

- 让游客和零售用户快速完成“发现商品、查看关键事实、加入购物车、提交订单、查看订单状态”的闭环。
- 让审核通过的批发客户无需手动切换模式，自动看到适用的批发价、起订量和必要阶梯价。
- 让多商家购物车清楚呈现商家边界，提交一次后形成可分别跟踪的商家子订单。
- 用简洁、清晰、可预测的现代 iPhone App 设计语言承载商品信息；关键购买事实优先于装饰。
- 在手机上保持单手可操作，在桌面上扩展为高密度但易扫描的内容区。
- 为中/意/英三语、深色模式、文字放大、减少动态效果、键盘操作和离线/失败恢复预留明确行为。

### 1.2 非目标

- 本轮不设计商家后台、入驻审核后台、商品导入、库存维护、采购、财务或运营工作台。商家未来可拥有管理店铺的能力，但本规范只约束买家客户端。
- “微信电商管理”仅作为业务说法；不设计微信商品导入、微信订单同步、微信 API、微信登录或相关授权。
- 不直接复制 Apple 商标、Logo、专有图标、系统截图或未授权资源；只借鉴移动系统的层级、留白、触控和材质原则。
- 不在本轮定案支付渠道、税务规则、物流供应商、退款政策、商家结算或外部 ERP 对接。结算页只定义客户端需要表达的状态和信息边界。
- 不用大 Hero、营销式首屏、渐变装饰、全页面玻璃化、嵌套卡片或信息墙扩大范围。

## 2. 设计原则

1. **首屏只服务一个主要任务。** 首页的主要任务是进入商品发现；商品详情的主要任务是确认是否值得购买；结算的主要任务是确认商家分组、收货和金额后提交。
2. **内容层清楚，材质层克制。** 商品、价格、库存和订单事实使用不透明内容面承载；半透明只用于导航栏、底部导航和临时 Sheet 等浮层。
3. **先显示购买决策所需事实，再显示次要细节。** 次要规格、政策和操作进入折叠区、详情页或底部 Sheet，但二手设备的成色、缺陷、电池健康和保修不能被折叠到用户看不到。
4. **角色差异自动发生。** 零售和已认证批发客户看到不同的有效价格；批发价、起订量和阶梯价由身份和商品规则决定，不设置“零售/批发模式”切换。
5. **商家边界不可模糊。** 商品卡、详情、购物车、结算和订单均显示商家归属；一个购物车提交后应能回到各商家子订单。
6. **状态和错误是设计的一部分。** 空、加载、库存变化、权限不足、离线和重复提交均有可理解的说明与恢复动作。
7. **三语优先于视觉挤压。** 意大利语和英语可能比中文更长；布局应允许换行、扩展或下钻，不能用裁切、过小文字或仅图标解决溢出。
8. **可访问性与效率同时成立。** 所有关键区域具有语义标签、可见焦点、至少 44px 舒适触控区和键盘顺序；密度由信息层级控制，不靠微小控件堆叠。

## 3. 视觉 Token 建议

Token 是后续视觉原型和实现的基线。本文件的品牌色与受控渐变由已批准的 `docs/12-Rebuy统一UI设计系统.md` 配色 D「循环翡翠青」覆盖；历史中性材质、信息层级、布局和交互规则继续有效。具体实现不得突破语义和对比度要求。

### 3.1 颜色

默认采用中性内容面配循环翡翠青行动色；页面不使用全页背景渐变，品牌渐变只按 docs/12 白名单使用。

| Token | 浅色建议 | 深色建议 | 用途与限制 |
|---|---|---|---|
| `color.canvas` | `#F6F6F8` | `#111113` | 页面底色；不承载主要正文对比 |
| `color.surface` | `#FFFFFF` | `#1C1C1E` | 商品、列表、表单内容面；默认不透明 |
| `color.surfaceElevated` | `#FFFFFF` | `#2C2C2E` | Sheet、弹层、被选中的内容区 |
| `color.textPrimary` | `#1C1C1E` | `#F5F5F7` | 标题、价格、主要正文 |
| `color.textSecondary` | `#636366` | `#AEAEB2` | 辅助说明、规格、时间 |
| `color.textTertiary` | `#8E8E93` | `#8E8E93` | 非关键提示；不用于必读购买事实 |
| `color.separator` | `#D1D1D6` | `#38383A` | 分隔线；不单独表示错误或可点击 |
| `color.action` | `#087F72` | `#53D1BE` | 循环翡翠青主行动、链接、选中状态；页面中有节制地使用 |
| `color.actionPressed` | `#05564E` | `#35B8A5` | 主行动按下/高对比状态 |
| `color.success` | `#2B7D32` | `#7FDB8F` | 已完成、有货、成功；与品牌翡翠青保持语义区分 |
| `color.warning` | `#9A5B00` | `#FFC05C` | 库存紧张、价格即将变化 |
| `color.danger` | `#B3261E` | `#FF8A80` | 错误、无货、不可提交 |
| `color.focus` | `#087F72` | `#53D1BE` | 2px 键盘焦点环；深色与 action 共值；不依赖颜色作为唯一提示 |

规则：正文与背景需达到 WCAG 2.2 AA 对比度；普通文字至少 4.5:1，大号文字至少 3:1。成功、警告、错误必须同时配合文字或图标，不得只用红/黄/绿区分。

### 3.2 字体与文字层级

使用设备系统字体栈，不捆绑专有字体文件。建议栈：

```text
-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB",
"Microsoft YaHei", "Noto Sans", "Segoe UI", sans-serif
```

| 层级 | 尺寸/行高 | 字重 | 使用场景 |
|---|---:|---:|---|
| `display` | 28/34px | 700 | 仅页面主标题；不用于普通卡片 |
| `title` | 20/28px | 650 | 分区标题、商品详情名称 |
| `headline` | 17/24px | 600 | 商品名称、订单状态、主要数字 |
| `body` | 15/22px | 400 | 主要说明和表单正文 |
| `bodyEmphasis` | 15/22px | 600 | 价格、数量、关键事实 |
| `caption` | 13/18px | 400 | 时间、规格辅助信息 |
| `micro` | 12/16px | 600 | 状态标签；不承载完整购买条件 |

最小可读正文不低于 13px；不使用视口宽度缩放字体。文字放大时允许自然换行、增加行数和页面高度，不能裁切或用省略号隐藏关键事实。

### 3.3 间距与版心

- 基础单位为 4px；常用间距为 4、8、12、16、20、24、32px。
- 页面水平内边距：手机 16px，宽度超过 768px 后 24px，桌面内容版心最大 1200px。
- 商品卡内部间距 12px；同一信息组 8px；信息组之间 16px；主要分区之间 24px。
- 手机底部导航和固定行动栏要避开安全区；内容底部至少预留 80px，避免被固定操作遮挡。
- 触控目标最小 44px × 44px，图标可以小于 44px，但可点击容器必须达到该尺寸。

### 3.4 圆角、边框与阴影

- 只使用 0、4、8px 圆角；卡片最大 8px，按钮、输入框和 Sheet 也不超过 8px。
- 避免无意义的胶囊形标签和超大圆角；标签使用 4px 圆角，状态仍以文字为主。
- 默认使用 1px 分隔线；浮层可使用一层轻微阴影或边框，不叠加多层阴影。
- 页面分区不做“卡片包页面”；卡片只用于单个商品、商家分组、订单项等真正需要框定的重复项。

### 3.5 图标

- 采用开源线性图标库或自有绘制的基础线性图标，例如 Lucide/Tabler 风格；先确认许可证，再进入实现。
- 常规图标尺寸 20px，导航和主要行动 24px；笔画 1.75–2px，保持同一视觉重量。
- 不复制专有系统图标的路径、Logo 或资源；“返回、搜索、筛选、购物车、订单、我的”等均用可替代的通用线性符号。
- 图标不是唯一信息载体：重要操作配文字或可访问名称；熟悉的纯图标操作提供 tooltip/辅助文本。

### 3.6 材质

| 材质层 | 建议表现 | 可用位置 | 禁止事项 |
|---|---|---|---|
| 不透明内容面 | `surface` 背景、清晰边界 | 商品、详情、表单、订单、空状态 | 不做背景模糊 |
| 半透明导航 | 背景不透明度约 72–88%，可选背景模糊 | 顶部导航、底部导航 | 不压低正文对比度 |
| 半透明 Sheet | 约 88–96%，配实色回退和拖拽/关闭方式 | 筛选、规格、语言、配送选项 | 不把完整页面套进玻璃层 |
| 遮罩 | 低透明度中性色 | 模态确认、错误阻断 | 不用于普通内容装饰 |

`backdrop-filter` 不是可用性的前提；不支持或关闭透明效果时，回退为不透明 `surface`。严禁全页面玻璃化、磨砂背景、渐变光晕和装饰性模糊。

### 3.7 动效

- 快速反馈 120–160ms，页面/Sheet 过渡 200–240ms；使用自然的 ease-out，不做弹跳式过度动效。
- 只动画化状态变化、层级进入和操作反馈；不自动轮播、不持续闪烁、不因装饰产生运动。
- 支持“减少动态效果”：关闭非必要位移和模糊，保留即时状态文字和焦点变化。
- 加入购物车、数量变化和提交订单必须先有同步可见反馈，再允许异步加载；不能用动画替代成功/失败文本。

## 4. 信息架构与导航

### 4.1 最终底部导航选择

底部导航最多 5 项，最终选择：**首页、分类、订单、购物车、我的**。

| 项目 | 主要任务 | 入口规则 |
|---|---|---|
| 首页 | 进入商品发现和最近活动 | 默认落点；提供全局搜索入口 |
| 分类 | 按商品类型/场景浏览 | 提供分类层级、筛选和排序 |
| 订单 | 查看订单批次、商家子订单和状态 | 订单状态角标只显示数量，不塞入文字 |
| 购物车 | 查看按商家分组的待购商品 | 右上角和底部均可进入；数量角标不超过两位数加 `+` |
| 我的 | 身份、批发认证、地址、语言和设置 | 不把后台管理入口伪装成买家功能 |

**搜索不占用底部导航位。** 搜索是跨页面的高频操作，放在首页首屏和分类/结果页顶部；桌面端放在内容区顶栏。这样保留搜索可达性，同时避免首页、分类、搜索、购物车、订单、我的六项拥挤在底部。

### 4.2 页面层级

```text
客户端
├── 首页
│   ├── 全局搜索入口
│   ├── 分类快捷入口
│   └── 推荐/最近浏览商品
├── 分类
│   ├── 分类目录
│   ├── 分类结果
│   └── 筛选/排序 Sheet
├── 搜索
│   ├── 搜索输入与建议
│   └── 搜索结果
├── 商品详情
│   ├── 普通商品事实
│   └── 二手设备事实
├── 购物车与结算
│   ├── 按商家分组购物车
│   ├── 地址/配送/金额确认
│   └── 提交结果
├── 订单
│   ├── 订单批次/商家子订单列表
│   └── 子订单详情
└── 我的
    ├── 身份与批发认证
    ├── 地址簿
    ├── 语言与显示设置
    └── 帮助/退出
```

### 4.3 导航行为

- 顶部返回遵循页面栈；返回不丢失搜索词、筛选项或购物车编辑状态。
- 底部导航切换保留各主页面滚动位置；进入详情、Sheet 或结算时不隐藏当前上下文。
- 破坏性操作（删除购物车项、取消订单、退出）使用轻量确认，不使用复杂多级弹窗。
- 筛选、语言、配送选项等短任务使用底部 Sheet；需要连续填写或产生订单的流程使用独立页面。
- 订单从一次提交产生多个商家子订单时，列表先显示订单批次，再允许下钻到每个商家子订单。

### 4.4 移动 App 标题层级（2026-08-25 Owner 修订）

- Owner 原话：`整个项目当中不要出现类似这样的目录，我要的是移动端app的那种体验`。
- 本决定中的“目录”指 `REBUY / CATALOG`、`Rebuy / cart`、`Rebuy / orders`、`Rebuy / local sample` 等路径/面包屑式过线标签，以及首页/详情/结账/订单/个人页中仅作装饰的 `01`/`02`/`03` eyebrow；不指商品分类、分类筛选、订单批次/商家子订单、个人身份分支或五项底部导航。
- 买家主页面直接显示本地化 `h1`/`h2` 和必要的结果数、购物车数、订单数或个人图标；装饰性路径标签不参与信息层级。
- 具体分类、商品分类入口和五项底部导航仍是业务导航，必须保留且可访问；删除的是装饰/路径表达，不是业务能力。

### 4.5 统一选择器（G0 修订，2026-08-25）

- Owner 原话：`这个点击打开的选项卡不统一 帮我为项目制作统一风格的`。分类排序和顶部语言入口必须共用 Rebuy `SelectMenu<T extends string>`，不得让浏览器原生展开层承担产品视觉。
- 选择器触发器/菜单/选项使用循环翡翠青 token、浅深色 surface、细边框、12–14px 圆角、柔和阴影和 selected `accent-soft`；每项与触发器操作区至少 44px。菜单使用 `menu`/`menuitemradio` 语义，支持当前项聚焦、方向键、Home/End、Enter/Space、Escape、外部关闭和 Tab/Shift+Tab 的正常文档移焦。
- 本轮不改变排序值、语言同步、商品筛选、分类入口、五项底部导航或业务数据；当前实测结果见[统一选择器实时验收 manifest](./evidence/G0-P1/2026-08-25-unified-select/README.md)，G0 本轮仍待 Owner 验收，不等于 UI 冻结或 G1 开放。

## 5. 角色可见性矩阵

角色定义：游客未登录；零售用户已登录但不是批发认证用户；已认证批发用户已通过审核且认证仍有效。批发身份失效时按零售规则显示，并给出认证状态说明。

| 能力/信息 | 游客 | 零售用户 | 已认证批发 |
|---|---|---|---|
| 浏览首页、分类、搜索、详情 | 可用 | 可用 | 可用 |
| 查看零售价 | 可见 | 可见 | 可见，作为必要的价格参照或按规则隐藏重复项 |
| 查看批发价 | 不可见 | 不可见 | 自动可见 |
| 查看起订量 | 不可见或显示“登录后查看批发条件” | 不可见或显示认证提示 | 自动可见，未满足时清晰提示 |
| 查看阶梯价 | 不可见 | 不可见 | 仅在商品存在阶梯规则时显示 |
| 加入购物车 | 可加入当前设备临时购物车 | 可加入账户购物车 | 可加入账户购物车 |
| 调整普通商品数量 | 可用，按当前可见零售规则 | 可用 | 按批发起订量、阶梯和库存规则可用 |
| 购买二手设备 | 可查看并加入；结算前需登录 | 可用 | 可用，仍按单件规则 |
| 提交订单 | 不可；在结算提交处要求登录 | 可用 | 可用 |
| 查看自己的订单 | 不可；显示登录入口 | 可用 | 可用 |
| 申请/查看批发认证 | 可申请/查看入口 | 可申请/查看状态 | 查看认证状态和适用规则 |
| 管理店铺、商品、库存、商家设置 | 不可 | 不可 | 不可；属于未来商家后台 |

价格、起订量和阶梯价不得通过手动模式切换控制。用户界面应显示“当前适用价格”及必要的条件，例如“批发价，起订 5 件”；若认证状态刚变化，提交前再次校验。

## 6. 商品卡片字段优先级

### 6.1 通用优先级

| 优先级 | 字段 | 展示规则 |
|---|---|---|
| 始终显示 | 商品主图或明确占位图 | 统一比例；无图时不使用误导性图库图 |
| 始终显示 | 商品名称、关键型号/规格 | 最多两行；关键型号不能被省略号吞掉 |
| 条件显示 | 二手类型/成色摘要 | 仅二手商品显示“二手”类型和成色摘要；普通商品不额外显示“普通商品”标签，避免无效信息 |
| 始终显示 | 商家名称 | 让用户知道商品归属；示例商家名称必须为虚构内容 |
| 始终显示 | 当前角色适用价格、计价单位 | 批发客户直接显示批发价；零售客户显示零售价 |
| 始终显示 | 可购买状态 | “有货”“库存紧张”“暂时无货”；不能只显示颜色 |
| 条件显示 | 起订量、阶梯价摘要 | 仅批发客户且规则存在时显示；不挤压商品名称和价格 |
| 条件显示 | 促销、配送时效、规格标签 | 有可信数据且对当前购买有帮助时显示 |
| 条件显示 | 二手成色、缺陷摘要、电池健康摘要 | 二手商品有该事实时必须显示至少一行摘要 |
| 详情页显示 | 完整规格、库存说明、卖家政策、配送与售后 | 在详情页按信息组展开；关键二手事实仍在上方 |
| 后台才显示 | 采购成本、毛利、仓位、供应商批次、内部审核备注 | 不进入买家客户端；不得通过前端隐藏而误认为安全控制 |

### 6.2 价格与数量

- 价格显示货币符号和计价单位，例如“€12.90/件”；不展示未授权的内部成本或毛利。
- 已认证批发客户看到“批发价”，需要时在其下显示零售价对照、起订量和阶梯价。零售用户不看到批发价格占位。
- 普通商品卡可显示“可购 12 件”或“库存紧张”，但详细库存数字只有在可信且不会造成误解时显示。
- 二手商品不显示可加购数量选择器；卡片标出“单件”或“仅 1 件”，详情页数量固定为 1。

## 7. 普通商品与二手设备的显示差异

### 7.1 普通商品

- 库存模型按数量管理；数量步进器支持最小购买量、最大可购量和库存上限。
- 商品卡显示名称、型号/规格、商家、适用价格、可购买状态；批发条件按角色显示。
- 详情页显示规格、包装/单位、可购数量、配送和售后说明；阶梯价使用简洁的表格或展开区。
- 数量、价格或库存变化后，购物车必须重新计算并明确提示变化原因。

### 7.2 二手设备

二手设备的购买关键事实不能被“简洁”隐藏。以下事实至少在商品详情首屏可见，存在时商品卡也应有摘要：

- 成色等级与可读说明，例如“成色 B：边框有可见磕碰”。
- 缺陷、维修史或功能限制；没有缺陷时明确显示“未发现已披露缺陷”，不能留白造成误解。
- 电池健康或容量检测结果；无法检测时写“未提供检测结果”，不能推测。
- 保修范围、期限和不包含事项。
- 商品为单件，数量固定为 1；被其他用户锁定、售出或失效时阻止继续提交。
- 真实可供购买的图片组应包含整体、屏幕、边框、缺陷近照和配件情况；本规范只定义位置，不提供真实图片。

二手商品详情的关键事实模块位于价格和主要购买操作附近，不放到页面底部、不只放在 tooltip、不只用图标表示。用户未展开折叠时也必须看到成色、缺陷、电池和保修摘要。

## 8. 关键组件与状态

### 8.1 组件清单

| 组件 | 必须承担的任务 | 关键行为 |
|---|---|---|
| App Shell | 提供标题、返回、搜索/购物车入口、底部导航 | 保留导航上下文，适配安全区 |
| SearchField | 输入商品/品牌/型号并提交 | 支持清除、键盘提交、历史为空状态 |
| ProductCard | 快速比较商品并进入详情/加入购物车 | 价格和库存优先；二手事实不可缺席 |
| PriceBlock | 解释当前角色的价格和条件 | 展示零售/批发、起订量、阶梯价来源 |
| SellerGroup | 在购物车和订单中明确商家边界 | 显示商家小计、配送/限制和子订单入口 |
| QuantityStepper | 调整普通商品数量 | 最小/最大/库存规则有文本反馈；二手禁用并说明 |
| UsedFacts | 集中表达二手购买事实 | 成色、缺陷、电池、保修均可读且可访问 |
| FilterSheet | 选择分类、价格、品牌、库存等 | 应用/清除状态明确，关闭不丢未提交选择 |
| StatusBanner | 反馈库存、网络、价格和权限状态 | role=status/alert；文字描述原因和动作 |
| SubmitBar | 固定显示关键小计和主要行动 | 避开安全区；提交期间防重复 |

结算确认规则：普通订单不额外增加确认阻力；只有二手商品存在已披露缺陷，且未来业务/法律规则确认确实需要时，才在对应商家组内显示明确的缺陷确认。不得在全局总计下设置笼统的“我已核对商品事实与条件”确认。

### 8.2 状态行为

| 状态 | 触发 | 用户看到的内容 | 可恢复动作 |
|---|---|---|---|
| `loading` | 首次进入、刷新、筛选或提交校验 | 与最终布局相近的骨架；关键区域保留标题语义 | 等待；超过合理时间显示“仍在加载”和重试 |
| `empty` | 无搜索结果、无订单、空购物车、无地址 | 说明当前范围和下一步；不责怪用户 | 清除筛选、去分类、去购物或新增地址 |
| `error` | 服务异常、数据解析失败 | 简短原因、影响范围和错误编号（如有） | 重试；保留用户已填写的本地内容 |
| `offline` | 无网络或请求断开 | 顶部可读横幅；区分“可看缓存”和“不能提交” | 恢复网络后重试；提交类操作禁用并说明 |
| `out of stock` | 当前商品无可用库存 | 价格区显示“暂时无货”，主操作禁用；二手显示已不可购买 | 返回列表、关注替代商品（若 V1 已批准）或移出购物车 |
| `low stock` | 库存低于商品规则阈值 | 显示“库存紧张”和可购买上限；不制造倒计时焦虑 | 调整数量；提交前再次校验 |
| `403` | 未登录、批发资格不足或资源无权限 | 说明是权限/身份问题，不显示内部详情 | 登录、查看认证状态或返回公开商品 |
| `duplicate submit` | 用户重复点击或网络重试导致相同提交 | 只保留一个提交状态；成功后显示订单批次，处理中不重复扣库存 | 查询原提交结果；不要创建第二个订单 |
| `price changed` | 结算前角色、阶梯或商家价格变化 | 逐商家/逐商品指出旧值和新值，要求确认 | 返回购物车确认；不静默改价 |
| `stale stock` | 打开详情后库存已被购买 | 阻止提交，说明库存刚刚变化 | 删除该项、调整数量或返回列表 |

状态文字必须可读、可聚焦；禁用按钮同时给出原因，不能只降低透明度。失败重试不应清空搜索词、表单、购物车编辑或已选筛选。

## 9. 响应式与三语规则

### 9.1 响应式断点

| 宽度 | 布局策略 |
|---:|---|
| 320–374px | 单列列表；商品卡减少次要字段，但保留价格、库存、商家和二手事实摘要 |
| 375–767px | 默认手机布局；列表可使用两列商品网格，但只有在名称、价格和状态不拥挤时启用 |
| 768–1023px | 平板/窄桌面；内容区可两栏，固定行动栏转为内容底部区域 |
| 1024–1279px | 桌面双栏或三栏；详情页图片区与购买信息并列，订单支持表格式扫描 |
| 1280px 以上 | 最大 1200px 版心；两侧留白，不拉伸单个卡片，不添加营销 Hero |

手机优先不等于桌面放大版。桌面应增加比较和扫描空间，但不新增买家功能；固定宽高组件使用稳定的网格、最小高度和 `aspect-ratio`，避免文字放大导致跳动。

### 9.2 中/意/英规则

- 所有用户可见文案均可翻译；商品名称、商家名和用户输入保持原文，但界面标签必须进入语言资源。
- 预留意大利语/英语比中文多 30%–40% 的长度；按钮允许换行，超过容器时改为两行或扩展高度，不能裁切。
- 同一页面只使用一种界面语言；不要中意英混排来节省空间。品牌/型号等业务原文可保留。
- 金额统一按用户当前结算货币规则显示；意大利语使用本地化小数和千位分隔，金额旁保留 `EUR/€` 的明确性。
- 日期、时间、数量和单位使用 locale 格式化；库存数量不能因格式化被误读。
- 语言切换不丢失购物车、搜索词和填写中的非敏感表单；切换后重新排版并保留焦点附近上下文。
- 语言、文字大小、深色/浅色和减少动态效果放在“我的 > 设置”；系统设置优先，应用内选择只作为覆盖项。

## 10. 无障碍要求

- 目标为 WCAG 2.2 AA 级的客户端实践；普通文字对比度至少 4.5:1，大号文字至少 3:1。
- 所有可交互元素最小 44px × 44px；相邻图标按钮留出足够间距，避免误触。
- 结构使用正确的标题层级、列表、按钮、链接、输入框、对话框和状态区域语义；商品卡不把整张卡伪装成无标签的大按钮。
- 键盘可完成搜索、筛选、加购、数量调整、结算确认和订单查看；Tab 顺序符合视觉顺序，Enter/Space 触发按钮，Escape 关闭 Sheet/模态并返回焦点。
- 始终显示 2px 可见焦点环；焦点不能被半透明导航或固定底栏遮挡。
- 文字放大至至少 200% 或系统大字模式时，关键字段不消失，按钮可换行，横向滚动只用于确实无法重排的数据表。
- 图片提供描述性替代文本；装饰图片标记为装饰；商品图缺失时占位文本说明“暂无商品图”。
- 不用颜色、位置、形状或动画作为唯一意义；库存、错误、二手缺陷和订单状态都提供文本。
- 状态更新使用 `status`/`alert` 语义并避免无意义重复播报；提交完成后把焦点移到订单批次标题或结果摘要。
- 支持减少动态效果、系统深色模式和高对比度倾向；透明材质关闭后仍可读。
- 触摸、键盘和辅助技术都能进入二手事实模块；不能只把缺陷放在 hover 或图片文字中。

## 11. 明确不采用的设计做法

- 不采用全页面毛玻璃、透明商品卡、背景模糊覆盖正文或依赖高端设备才能辨认的材质效果。
- 不采用大 Hero、营销式首屏、自动轮播、渐变背景、装饰性渐变按钮或没有任务意义的动效。
- 不采用信息墙、六项以上底部导航、把搜索塞进不可发现的菜单、或用多个浮动按钮同时争夺首屏注意力。
- 不采用嵌套卡片、卡片套卡片、超过 8px 的大圆角、无意义的胶囊按钮和过度阴影。
- 不采用仅图标且无名称的关键操作、不显示库存/价格条件的“立即购买”、或靠颜色区分订单/库存状态。
- 不采用让批发用户手动切换“批发模式”的设计，不把批发价以未认证用户可猜测的占位方式泄露。
- 不采用把二手商品成色、缺陷、电池健康、保修藏在页面底部、图片角落、tooltip 或默认折叠里的设计。
- 不采用通过极小字号、横向挤压、裁切或固定单行来掩盖三语长度差异。
- 不采用前端隐藏内部成本、仓位、供应商批次或审核备注作为安全边界；这些字段本就不属于客户端数据合同。

## 12. 设计验收清单

### 信息架构与范围

- [ ] 底部导航只有：首页、分类、订单、购物车、我的五项；搜索在首页/分类顶部可达。
- [ ] 首页、分类/搜索、商品详情、购物车/结算、订单、我的均有页面定义或在合理合并中可定位。
- [ ] 商家后台、微信导入/同步/API 和未审批的支付/ERP/税务扩展没有混入买家客户端。
- [ ] 每个页面首屏只有一个主要任务，次要信息有下钻、折叠或 Sheet 规则。

### 商品与购买

- [ ] 普通商品按数量库存，支持最小量、最大量和库存变化反馈。
- [ ] 二手设备按单件管理；成色、缺陷、电池健康、保修在详情首屏可见，存在时卡片有摘要。
- [ ] 游客/零售/已认证批发的可见性和价格规则明确；批发用户无需手动切换模式。
- [ ] 多商家购物车按商家分组，提交后可定位每个商家子订单。
- [ ] 价格变化、库存过期、无货、低库存和重复提交均有阻断/恢复动作。

### 视觉与交互

- [ ] 内容面默认不透明；半透明只用于导航、Sheet 等受控层，并有不透明回退。
- [ ] 卡片圆角不超过 8px；无渐变装饰、嵌套卡片或信息墙。
- [ ] 触控目标至少 44px；焦点环、键盘顺序、Escape 关闭和提交后焦点均可验证。
- [ ] 浅色/深色、文字放大、减少动态效果下，关键文字、按钮和状态仍可用。

### 三语与响应式

- [ ] 中文、意大利语、英语全部使用可替换文案；意大利语/英语扩展时不裁切、不遮挡。
- [ ] 至少检查 320px、390px、430px 手机宽度和 768px、1024px、1280px 桌面宽度。
- [ ] 桌面布局提升扫描效率但不引入后台工作台风格或额外业务目标。
