## 4. 品牌与 Logo brief

### 4.1 品牌气质

Rebuy 的视觉气质是“可信、清楚、快速比较、面向真实交易”。循环翡翠青用于行动和当前上下文，不用于掩盖价格、库存或二手事实。买家端强调发现与决策，商家后台强调操作与扫描；两者共用品牌，但不共用页面目标。

### 4.2 Logo brief

- 图标：抽象几何 `R`，由两个相互咬合的斜向/圆角路径构成，表达“重新流通、重购、连接多商家”。
- 颜色：主版本使用循环翡翠青实色或受控品牌渐变；深色模式使用提高亮度后的翡翠青版本。参考图原蓝紫层级仅保留为研究依据，不再作为当前 token。
- 形状：图标可放入 28–32px 圆角方形标记；不得复制 Apple 或参考素材的图标路径。
- 字标：`Rebuy`，系统无衬线、650–700 字重、清晰字距；不使用装饰字体。
- 使用：顶部品牌、登录/空状态和分享缩略图的设计 brief；本批次不创建 PNG/SVG 资产，不声称 Logo 已交付。
- 小尺寸：小于 24px 时只显示抽象 `R` 标记，并确保有可访问名称；不以图标代替关键操作文字。

## 6. 字体、间距与高密度规则

### 6.1 字体

使用系统字体，不捆绑专有字体文件：

`-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans", "Segoe UI", sans-serif`

| 层级 | 尺寸/行高 | 字重 | 典型用途 |
|---|---:|---:|---|
| `display` | 30/36px | 700 | 登录或页面主标题，不能用于每张商品卡 |
| `pageTitle` | 24/30px | 700 | 页面标题 |
| `sectionTitle` | 18/24px | 650 | 分区、商家组、设置组标题 |
| `cardTitle` | 16/22px | 650 | 商品、订单、后台行标题 |
| `body` | 15/22px | 400 | 正文、说明、表单 |
| `bodyEmphasis` | 15/22px | 600 | 价格、数量、关键事实 |
| `caption` | 13/18px | 400 | 商家、时间、规格辅助信息 |
| `micro` | 12/16px | 600 | 状态标签和小提示 |

最小可读正文不低于 13px。金额、库存、订单号和时间使用等宽数字特征（`font-variant-numeric: tabular-nums`）以便扫描。文字放大时允许换行和页面变高，不能用裁切或省略号隐藏二手事实、价格、库存或商家。

### 6.2 间距与密度

- 基础单位为 4px；标准节奏为 4、8、12、16、20、24、32px。
- APP 内容水平内边距 16px；PC 内容区水平内边距 24px；买家 PC 紧凑分类栏宽度建议 224px，未来商家后台侧栏宽度建议 248px。
- 商品卡内部 12px；同一字段组 8px；字段组之间 16px；主要分区之间 24px。
- 高密度来自对齐、分组、固定列、摘要和局部展开，不来自 11px 以下文字、过多边框或无关模块。
- PC 表格行默认 56–64px；可点击控件仍保持至少 44px 触控/键盘操作区。
- APP 普通商品双列；二手商品单列扩展卡；购物车、结算和订单按商家单列分组。
- 固定底部导航、Sheet 和行动栏需要预留安全区；内容底部不能被固定元素遮挡。

### 6.3 圆角、边框和阴影

- 主要内容卡使用 12px；Shell、Sheet 和 Modal 使用 16px；小标签可使用 8px。
- 使用 1px `color.border` 分隔，不使用粗重描边表达普通层级。
- 卡片默认无多层阴影；浮层使用一层轻阴影。建议浅色 `shadow.float = 0 12px 32px rgba(8, 95, 85, 0.12)`，深色 `shadow.float = 0 16px 40px rgba(0, 0, 0, 0.34)`。
- 页面不做“卡片套卡片”；只有商家组、商品、订单项、表格和表单区块等真正需要边界的重复项才使用卡片。

## 7. 两套 Shell

### 7.1 Buyer Shell

#### PC

- 左侧为紧凑分类导航，显示 Rebuy 标记、分类/场景入口和必要的账户入口。
- 顶部为全局搜索、语言/主题/账户等轻量工具和购物车入口；搜索不占用底部导航位。
- 主区为高密度商品流，首屏任务是搜索、分类和比较，不显示 KPI 仪表盘。
- 商品区使用普通商品紧凑卡和二手扩展卡；商家、价格、库存和关键事实不可被装饰遮挡。

#### APP

- 顶部保留页面标题、返回、搜索/购物车入口和必要状态。
- 底部导航固定五项：`首页、分类、订单、购物车、我的`。
- 当前项使用循环翡翠青圆角高亮；其他项保留小文字和图标，不做只有图标且无名称的关键导航。
- 普通商品使用双列；二手商品使用单列扩展卡；Cart/Orders 永远按商家单列分组。

### 7.2 Merchant Shell（未来设计映射）

- PC 使用 248px 左侧工作台侧栏、顶部组织/店铺上下文和工具栏、主区高密度表格/表单。
- 侧栏按工作区分组：工作台、商品、库存、订单、售后、成员与权限；不把后台入口显示在买家五项导航中。
- 订单、库存、成员和权限需要表格扫描；详情/编辑通过主区分栏、Modal 或 Sheet 进入。
- APP 只映射高频任务：待处理订单、库存异常、售后待办和成员审批；不把完整 PC 表格硬缩成不可读的横向页面。
- 后台 Shell 复用品牌和组件 token，但不复用买家首页信息架构，不显示买家购物车或买家订单导航。

## 8. 导航与基础组件规则

### 8.1 导航

- 买家一级导航固定五项，搜索在顶部；批发身份由系统自动决定价格，不提供“零售/批发模式”开关。
- 未来后台使用分组侧栏和顶部上下文，不新增未审批的业务模块。
- 返回不丢失搜索词、筛选、购物车编辑或表单上下文；深层任务可以使用 Sheet/Modal，但需要可关闭和焦点回归。

#### 8.1.1 移动 App 标题层级（Owner 2026-08-25 修订）

- Owner 原话：`整个项目当中不要出现类似这样的目录，我要的是移动端app的那种体验`。
- “目录”在本系统中指 `REBUY / CATALOG`、`Rebuy / cart`、`Rebuy / orders`、`Rebuy / local sample` 等路径/面包屑式过线标签，以及仅为 section heading 装饰的 `01`/`02`/`03` eyebrow；买家主页面直接显示本地化页面标题和业务上下文。
- 商品分类、筛选、订单批次/商家子订单、身份/会员语义分支和五项底部导航不是装饰目录，仍须保留；删除路径式与纯装饰表达，不删除业务导航或事实标签。
- 无 eyebrow 时标题不保留假性上间距；首个买家 `page-section` 不叠加额外 32px 空白，移动端优先保持原生 App 的直接分区节奏。

#### 8.1.2 买家端目录信息架构（G0 重新打开修订）

- Owner 新要求原话：`然后网站整体的目录结构应该是跟淘宝类似，首页显示推荐内容，然后分类展示各个种类的列表，点进去后才是商品`。这里只借鉴层级关系，不复制淘宝品牌、配色、拥挤营销或视觉。
- 买家发现路径固定为：`首页推荐 → 分类目录 → 点击品类进入商品列表 → 点击商品进入详情`。首页推荐区先于轻量快速分类；推荐内容仍使用既有商品卡和二手事实规则，不增加 KPI、营销墙或无关模块。
- 底部/桌面一级“分类”必须进入目录根页：只显示本地化品类列表/目录，不显示商品卡、结果数、筛选或排序。品类按钮至少 44px，支持键盘焦点和清晰的当前操作反馈。
- 点击品类进入该品类商品列表：显示本地化品类标题、结果数、筛选/排序和“返回全部分类”；不使用 `REBUY / ...`、面包屑/path label 或装饰数字。全局搜索可以直接进入搜索结果；首页快速分类和桌面侧栏具体品类可以直接进入对应列表。桌面侧栏中的品类是快捷入口/当前已知品类子集，不替代“分类”一级导航打开的完整目录根页。
- 从商品列表进入详情、返回时保留来源品类结果上下文；五项买家导航、二手成色/缺陷/电池/保修、批发身份自动定价、多商家分组和 zh/it/en 不因目录层级改变。
- 当前状态：分类目录 IA 修订及主代理本地浏览器复验已完成，Owner 最新决定已将 G0/P1 更新为“已通过并冻结”，G1 Entry 已恢复并进入“准备中”。点击搜索已通过，直接 Enter 键盘提交未验证成功并转入后续键盘/无障碍专项，不阻塞本次冻结。本条是设计合同，不替代专项或工程 Gate；证据见[分类目录 IA 记录](./evidence/G0-P1/2026-08-25-category-directory-ia/README.md)与[G1 Entry 基线](./evidence/G1/2026-08-25-entry-baseline/README.md)。

### 8.2 按钮和控件

- 主按钮使用 `color.action` + 对应的 `color.onAction`；深色模式不能默认沿用浅色白字。次按钮使用不透明 `surface` + `border`；危险实心操作使用 `color.danger` + 对应的 `color.onDanger`，危险文字按钮使用明确文字和图标。
- 按钮、输入、选择器和图标按钮的可操作容器至少 44×44px；圆角 12px。
- 主要行动应有文字；熟悉的辅助图标可以单独使用，但必须有可访问名称和 tooltip/辅助文本。
- 禁用状态同时显示原因；不能只降低透明度后让用户猜测不可用原因。
- 状态标签同时使用文字、图标和语义色；颜色不是唯一信息载体。

### 8.3 商品卡和二手事实

- 普通商品紧凑卡：商品图、名称/型号、商家、当前角色适用价格、计价单位、库存状态和加购入口。
- 二手扩展卡：以上字段加成色、缺陷、功能限制、电池健康、保修和单件规则；这些事实直接可见，不放默认折叠或 tooltip。
- 已认证批发用户自动看到批发价、起订量和阶梯价；游客/零售用户不看到可推测批发价格的占位信息。
- 普通商品可使用数量步进器；二手商品固定为 1，售出/锁定/库存失效时给出原因和恢复路径。
- 商品内容面不使用装饰性渐变、透明背景或模糊；图片缺失时使用明确的无图状态。

### 8.4 表格、表单和筛选

- 后台表格使用浅灰表头、细网格、对齐数字列、状态标签、分页和行级操作；列多时优先隐藏次要列或进入详情，不压缩关键字段。
- 买家端购物车/订单优先使用商家分组卡；仅真正需要比较的后台数据使用表格。
- 表单采用上置标签、帮助文本、字段级错误和保存状态；敏感或内部字段不进入买家 DTO。
- Filter/Sort 使用顶部工具栏或 Sheet；应用、清除和当前筛选状态始终可见。

#### 8.4.1 统一选择器 SelectMenu（G0 修订）

- 排序、语言以及未来经 Owner 批准的同类短选项必须共用一个 Rebuy `SelectMenu<T extends string>` Client Component；不得在买家端重新实现各页独立下拉菜单。
- 产品选择器禁止使用浏览器原生展开层作为视觉实现；触发器、弹层和选项统一使用循环翡翠青 token、`surface`、`border`、12–14px 圆角、柔和阴影、selected 的 `accent-soft` + Check、hover/focus 和 Chevron 状态。
- 语义必须是 button + `aria-haspopup="menu"`/`aria-expanded`/`aria-controls`，弹层 `role="menu"`，选项 `role="menuitemradio"` + `aria-checked`；支持当前项聚焦、ArrowUp/ArrowDown、Home/End、Enter/Space、Escape、Tab 自然移焦和点击外部关闭。
- 弹层应安全贴合入口、右对齐时不越出视口，移动端宽度/高度受视口约束；触发器和选项操作区至少 44×44px。浅色/深色均使用同一语义 token，不改变排序值、语言值或筛选业务。

#### 8.4.2 统一选择器本轮实测与当前 Gate（2026-08-25）

- Owner 原话：`这个点击打开的选项卡不统一 帮我为项目制作统一风格的`。本轮已用共享 `SelectMenu<T extends string>` 替换排序/语言原生选择器，主代理实时浏览器复验结果见[证据 manifest](./evidence/G0-P1/2026-08-25-unified-select/README.md)。
- 499×862 浅色分类排序菜单实测为 3 项、1 项选中、`212×150`、圆角 14px、每项 44px、视口内且无系统蓝色；390×844 深色菜单视口内、`scrollWidth=clientWidth=390`，背景/边框为主题化中性面；1440×900 语言菜单右对齐不越界，zh-CN/it/en 键盘切换并同步标题。
- ArrowDown+Enter、End、Home、Escape、筛选 Sheet 联动及 Tab/Shift+Tab 均实测；390/1440 的 Tab 一次关闭并按正常文档顺序移焦，不落 BODY。控制台无 warning/error；typecheck/lint 通过；原生 `<select>` 扫描为 0。
- 本批是 G0 低风险视觉/交互修订；统一选择器与分类目录 IA 的主代理本地浏览器证据均已完成，Owner 已决定 G0/P1 通过并冻结；点击搜索已通过，直接 Enter 键盘提交未验证成功并转入后续专项。G1 Entry 已恢复，但当前只准备 G1.1，未运行本批或 G1 工程 build/E2E，未启动额外独立审查代理；分类目录证据见[记录](./evidence/G0-P1/2026-08-25-category-directory-ia/README.md)，G1 基线见[Entry 证据](./evidence/G1/2026-08-25-entry-baseline/README.md)。

### 8.5 Sheet、Modal、状态和图表

- APP Sheet 从底部进入，16px 顶部圆角，实色回退；PC 可使用居中 Modal。关闭后焦点回到触发元素。
- `loading` 保留接近最终布局的骨架；`empty` 提供下一步；`error` 提供重试并保留上下文；`offline` 区分可看和不可提交；`403` 说明身份/权限动作；`price changed`、`stale stock`、`duplicate submit` 指向具体商品/商家并提供恢复。
- 图表只用于后台或明确的报告上下文；每个图表必须有标题、单位、图例和文字摘要，不能用颜色/悬停作为唯一信息。
- 关键统计不应在买家首页占据首屏；买家首页只保留搜索、分类和商品流。

## 9. 动效合同

- 动效基线：按钮和状态反馈 120–160ms；Sheet、Modal、卡片层级 200–240ms；使用自然 ease-out，不使用弹跳和持续闪烁。
- 允许导航项高亮、卡片轻微进入、Sheet/Modal 上移、受控渐变轻微位移和状态反馈；不自动轮播、不让商品事实随装饰移动。
- `prefers-reduced-motion: reduce` 时关闭非必要位移、模糊、渐变动画和滚动平滑，只保留即时文字、焦点和状态变化。
- 动效不替代成功/失败文字；加入购物车、价格变化、库存变化和提交状态必须同步可读。

## 10. 三语与无障碍

- 所有界面文案支持中文、意大利语、英语；商品名、商家名、型号等业务原文可以保留。
- 为意大利语和英语预留比中文更长的文本空间；按钮允许换行，不能裁切、遮挡或用小于 13px 文字解决溢出。
- 金额、日期、时间、数量和单位按 locale 格式化；价格仍清楚表达 EUR/€ 和计价单位。
- 所有互动容器至少 44×44px；支持键盘 Tab/Enter/Space/Escape、可见焦点、语义标题、列表、按钮、表单、Dialog 和状态区域。
- 商品图和 Logo brief 未来交付时必须有替代文本；装饰图片标记为装饰。
- 深色模式、文字放大、减少动态和无透明材质回退时，价格、库存、商家、二手事实和状态仍可读。
- 实现验收前必须实际检查最终字体/字号/背景/状态组合的对比度；此文档不把 token 表本身视为对比度证明。

## 11. 禁止项

- 不把参考后台的工作台导航、KPI 仪表盘、团队、审批、计费、AI 模型或时间跟踪功能放进买家端。
- 不改变买家五项导航，不加入手动批发模式，不隐藏商家分组和订单子订单。
- 不把二手成色、缺陷、电池、保修藏在默认折叠、tooltip、图片角落或页面底部。
- 不对商品/价格/库存/结算/订单内容面使用全页渐变、玻璃化、背景模糊或持续光晕。
- 不使用只有颜色的库存、错误、订单或售后状态；不以前端隐藏内部字段作为安全边界。
- 不使用参考素材中的第三方 Logo、头像、截图、文案、真实数据或未经授权资产。
- 不用横向挤压、固定单行或省略号掩盖三语长度差异和关键购买事实。
- 不在本设计系统文档中声称代码、后端、数据库、支付、部署或生产数据已经实现。
